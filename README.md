# Tancode

A lightweight, local-first coding companion that helps developers learn technical concepts while vibe coding and understand errors without relying on their coding agent for every explanation.

Tancode is an educational assistant, not a code reviewer or autonomous coding agent. It explains problems and presents possible approaches; the developer decides what to do.

This repository currently contains the extension scaffold plus the learning panel: `Tancode: Explain Current File` opens a `Tancode` panel that explains the active source file, and `Tancode: Explain Selected Code` explains a selected range with three actions — **Explain** (concise), **Learn** (a structured teaching breakdown), and **Test My Understanding** (a short practice question with feedback). By default everything is generated by a **local Ollama model** — nothing is sent to external services. If Ollama is unavailable, the panel shows an actionable error and (optionally) a clearly-labelled rule-based fallback. `Tancode: Hello World` remains as a scaffold sanity check.

## Local model setup

Tancode talks only to a local [Ollama](https://ollama.com) server over its HTTP API on `127.0.0.1`. No account, API key, or external network is used; the only request sent anywhere is the active file's or selection's text to `127.0.0.1:11434` (configurable).

1. Install Ollama (if not already installed) and make sure it is running:

   ```bash
   ollama serve   # or launch the Ollama app — check `ollama list` responds
   ```

2. Check which models you already have: `ollama list`. Any installed model works — pick one and set it in VS Code settings if it differs from the default.
3. Optionally pull the documented default candidate: `ollama pull qwen3:8b` (only if you want it; Tancode never downloads models itself).

### Settings (File → Preferences → Settings → search "Tancode")

| Setting | Default | Purpose |
| --- | --- | --- |
| `tancode.ollama.baseUrl` | `http://127.0.0.1:11434` | Local Ollama endpoint |
| `tancode.ollama.model` | `qwen3:8b` | Model name, must exist in `ollama list` |
| `tancode.maxSourceBytes` | `65536` | Files above this size are not sent to the model |
| `tancode.requestTimeoutMs` | `120000` | Per-request timeout |
| `tancode.fallbackToRuleBased` | `true` | Show the labelled deterministic fallback on model failure |
| `tancode.proactive.enabled` | `true` | Tancode may speak first: explain new editor errors, flag learning moments, ask a check question |
| `tancode.proactive.level` | `all` | `all` = errors + learning moments; `errors-only` = only diagnostics |
| `tancode.proactive.cooldownSeconds` | `90` | Minimum seconds between unsolicited messages |
| `tancode.proactive.maxPerSession` | `12` | Cap on unsolicited messages per panel session |

## Getting started

Requires Node.js 20+ (see `engines` in `package.json`; `.npmrc` enforces it) and a desktop VS Code install of version 1.90 or later.

From the repository root (the commands are identical on Windows, macOS, and Linux):

```bash
npm ci            # clean, reproducible install of dev dependencies
npm run compile   # build the extension to out/
npm run typecheck # type-check without emitting
npm run watch     # recompile on change (default build task)
```

To run the extension:

1. Open this folder in desktop VS Code.
2. Run `npm ci` and `npm run compile` once.
3. Press F5 to launch the Extension Development Host (`Run Extension` launch configuration; it runs the `npm: watch` build task first and waits for the TypeScript watch build to report ready).
4. In the Extension Development Host window, open the Command Palette (Ctrl+Shift+P) and run `Tancode: Explain Current File`.
5. The `Tancode` panel opens beside the editor and asks the local model for a short explanation of the active file. Switch tabs and the panel follows (results are cached per file version). Click "Explain in more detail" for a deeper pass.
6. **Explain selected code:** highlight some code and run `Tancode: Explain Selected Code` (Command Palette or right-click → the same entry, shown only when text is selected). The panel shows the file name and line range, then explains just the selection — with a few lines of surrounding context, kept clearly separate in the prompt. From a selection you get three actions:
   - **Explain** — a concise explanation of purpose, flow, inputs/outputs, and one key concept.
   - **Learn** — an expandable teaching breakdown: Purpose, How it works, Concepts to learn, Important details, Remember this.
   - **Test My Understanding** — a single reasoning question about the selection. Type an answer and submit; the model replies with what you got right, what to improve, and a reference answer (shown only after you submit). "Try another question" asks for a fresh one. Quiz state is never persisted.
   - **Back to file explanation** returns to the active-file view. File/selection explanations for an unchanged document are served from the in-memory cache; Retry always makes a fresh request.
7. If Ollama is stopped or the model is missing, the panel shows an "Explanation failed" banner naming the failure (unavailable, model missing, timeout, HTTP error, malformed) plus what to run (`ollama serve`, `ollama pull <model>`), and the labelled rule-based fallback.
8. Every result shows its source: **Generated by local model: \<model\>** for real inference (with a "cached result" note when served from the in-memory cache), or **Rule-based fallback** when the model failed. Per-request diagnostics — file name, mode, model, byte size, output cap, time-to-first-token when streaming, duration, and the outcome/failure category — go to the `Tancode` channel in View → Output. Source code and prompts are never logged.
9. `Tancode: Hello World` still works as a scaffold sanity check.

### The mentor panel

The Tancode panel is a conversation, not a one-shot display. Above the chat feed sits the pinned context card (the current file/selection explanation); below it, a feed of your questions and Tancode's answers plus its occasional proactive notes — each tagged as a learning moment, error, question, or feedback. Type in the composer at the bottom to ask anything; plain answers stream in. While anything is generating, the toolbar shows **Stop generation**.

**Proactive assistance** (all of it respects the pause toggle and the `tancode.proactive.*` settings):

- **New editor error** → a tagged error note explains what the diagnostic means, the likely cause at that line, the underlying concept, possible fixes (never applied), how to verify, and one follow-up question. Confirmed editor errors are distinguished from model inferences; the same unresolved error is never repeated.
- **Meaningful saved change** → if the model finds something genuinely worth learning, a dismissible learning moment appears; routine saves stay quiet.
- **After a Learn explanation** → at most one knowledge-check question per selection. Answer it in the chat box and get feedback on your reasoning.
- Hard limits: a configurable cooldown between messages and a per-session cap (`proactive 3/12` shows in the footer). If the model is busy or finds nothing worth saying, nothing posts.

The chat also understands natural commands routed through the same local model — "Explain what I'm looking at", "Give me the short version", "Why did this error happen?", "Pause proactive assistance", "Why are you telling me this?". Direct questions get direct answers, not forced lessons.

### Performance notes

The extension tunes each request for latency:

- `think: false` on every `/api/generate` call — skips qwen3's hidden thinking pass.
- Per-mode `num_predict` caps (summary 200 / detail 500 / selection 300 / learn 500 / question 180 / assessment 500) so short answers can't ramble.
- `keep_alive: 10m` keeps the model loaded between requests instead of reloading.
- Explanations stream: the first generated text appears as it arrives instead of after the full answer; a newer file, selection, or action cancels the stale request.
- The `Tancode` output channel logs `explain request:`, `explain first token:` (time to first byte), `explain cache hit:`, `explain dedupe:`, and `explain success:`/`explain failed:` with durations — the fastest way to find your bottleneck.

If `qwen3:8b` is still slow on your hardware, point `tancode.ollama.model` at a smaller installed tag from `ollama list`.

### If the panel only shows the rule-based summary

Check the `Tancode` output channel (View → Output): every request logs its endpoint, model, duration, and outcome (`explain success` or `explain failed: kind=…`). The most common causes on a fresh setup:

- `kind=timeout` — the whole generation must finish inside `tancode.requestTimeoutMs` (default 120s). An 8B model on CPU can exceed that on large files; raise the setting or use a smaller model.
- `kind=modelMissing` — the `tancode.ollama.model` setting doesn't match an installed tag from `ollama list`.
- `kind=unavailable` — Ollama isn't running, or `tancode.ollama.baseUrl` points somewhere else.
- No `explain request:` line at all — the extension host is running a stale build: run `npm run compile` and fully restart the Extension Development Host.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `'tsc' is not recognized as an internal or external command` (Windows) or `tsc: not found` | `node_modules` is missing — dependencies were never installed, so the local `tsc` binary doesn't exist. TypeScript is a project devDependency, not a global tool. | Run `npm ci` in the repository root, then retry. The `precompile`/`pretypecheck`/`prewatch` scripts now print this hint automatically. |
| `npm ci` fails with an `EBADENGINE` warning-as-error | Node.js is older than the `>=20` required by `engines`. | Install Node.js 20 or later from https://nodejs.org and reopen the terminal. |
| Compile errors after a clean install | TypeScript errors in source. | Run `npm run typecheck` to list them without emitting output. |
| F5 does nothing or no Extension Development Host window appears | The `npm: watch` prelaunch task hasn't finished its first build, or compilation failed. | Check the Terminal panel for the `npm: watch` task output; run `npm run compile` manually to see errors. Confirm `.vscode/launch.json` exists and `out/extension.js` was emitted. |
| `Tancode: Hello World` missing from the Command Palette in the Extension Host | The extension didn't activate or the command id doesn't match. | Confirm `contributes.commands[0].command` in `package.json` is `tancode.helloWorld` and matches `vscode.commands.registerCommand('tancode.helloWorld', ...)` in `src/extension.ts`. Check the Extension Host's developer console for activation errors. |

## Configuration

`.env` holds local runtime configuration (for example, the address of a future local inference runtime). VS Code extensions do not load `.env` files automatically — no code reads it yet. `.env` is git-ignored; `.env.example` documents the available variables with harmless placeholders.

## Roadmap

Planned features, in rough order (not implemented yet):

- **Error understanding** — explain VS Code diagnostics and source context: what the error means, where it originates, likely causes, possible fixes and trade-offs, and the underlying concept when useful. Confirmed diagnostic information is distinguished from inferred causes. Tancode never edits source files or applies fixes.
- **Lightweight experience** — unobtrusive and fast; no learning history, progress tracking, or knowledge-management system in the MVP.

## Privacy and security rules

- Never execute commands merely because they appear in source code or model output.
- Never execute a terminal command as part of explaining it.
- No automatic code modifications.
- Source code, comments, README contents, and model responses are treated as untrusted input.
- No environment variables or secrets are written to logs.
- No telemetry or external data transmission without an explicit, reviewed requirement.
